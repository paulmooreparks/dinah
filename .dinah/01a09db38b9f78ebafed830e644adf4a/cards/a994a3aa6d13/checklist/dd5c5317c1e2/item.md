note: "Agent Design Review raised this as the card's blocker and it is right. `samePath` in internal/bench/bench.go returns true when `os.Stat` fails for any reason other than not-existing, and its own doc comment says why: its one caller today is the upward walk, where true means stop climbing, so failing that way keeps a boundary the tool cannot check. On a containment test true means admitted, so the same function would admit any path the process cannot stat. OQ-3's recommendation to put the new code beside `samePath`, and the Go style standard's reuse rule, both point an implementer straight at it, so the spec has to say no in writing.\n\nWhat is ruled. The containment test answers `dinah.outside-root` when the root will not stat, when the resolved path will not stat, and when any ancestor between them will not stat, for any reason including a permission error, a disconnected volume, and a root removed after the server started. The walk stops at the first ancestor it cannot stat rather than skipping it and climbing on. The new code stats and compares on its own, and `samePath` gains one sentence naming it and saying the two want opposite failure postures.\n\nA parameterised helper taking the failure direction as an argument was considered and refused. A flag deciding which way a safety check fails is the thing that has to be legible where the check is made, and a shared function with two postures hides it behind a call site's argument list.\n\nThe seam is the second half of this decision and it was added at cycle 2. Every stat the containment test makes goes through an unexported package-level `statPath` in internal/bench, holding `os.Stat`, which a test replaces and restores through `t.Cleanup`. Without it no test can reach the failure this rule exists for. A test that creates the directories it compares never meets a failing stat, and the only failure it can force without a seam is not-exist, by removing a directory; not-exist is exactly the branch `samePath` already handles safely, since it returns `!errors.Is(err, os.ErrNotExist)` for a boundary that will not stat. A containment test that reused `samePath` in defiance of this decision would therefore pass a removed-root check and still admit every unreadable path. The seam also keeps the check portable, because how a platform reports an unreadable directory is not something this repository builds a check on. `readAnchorContent` in the same file is the precedent, added for that same reason, and `internal/bench/anchor_recognition_test.go` is the shape a test overriding it takes. AC-17 drives both branches and its note says which break reddens which clause.\n\nRepository claims verified for this decision: 4 (the body and doc comment of `samePath`, that its one caller today is the upward walk in internal/bench, that `samePath` returns false rather than true on a not-existing boundary, and the existence and stated reason of the `readAnchorContent` seam together with the two tests that override it)."

The containment test fails closed on every stat failure, it stats through a test seam, and samePath is not reused for it.
