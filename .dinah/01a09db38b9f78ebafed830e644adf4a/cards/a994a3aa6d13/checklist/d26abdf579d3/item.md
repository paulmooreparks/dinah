note: "Operator ruling (Paul, relayed by Devin on BARN), which settles the question this card was filed to ask rather than leaving it open.\n\nHis reasoning, in his words: a single running instance of a CLI call should be for one workbench only, but an MCP surface must be callable for multiple workbenches. He reads the present shape as a category error, and I agree with the diagnosis and want to place it precisely, because the spec is not at fault in the way it first appears.\n\nThe core profile's boundary row rules out views across several workbenches, and it is defensible on its own terms: it says the protocol defines no relationship between workbenches, which is a statement about cards and references. The error is downstream. The tool read a protocol scope boundary as an architectural constraint on a long-lived server surface, and those are different things. A CLI process is invoked once per command and dies; an MCP registration is configured once by a client and serves whatever that client asks for the rest of the session. Scoping the second the way the first is scoped forces one registration per workbench on every operator who runs more than one, which is the situation that produced this card.\n\nSo no part of the profile needs reopening. A head serving several workbenches breaks none of its rules, as long as no cross-workbench reference enters the core.\n\nTwo consequences this decision creates rather than resolves, and the spec for this card has to answer both.\n\nAn agent cannot ask for a workbench it cannot name. `workbenches`, the command that lists what is reachable, is one of seven deliberately excluded from the MCP surface as shell-only, so a workbench parameter on its own leaves an agent with an address space it cannot enumerate. Either that command joins the surface or something else answers the question.\n\nA head that can reach any workbench can reach the operator's own. Today the boundary is accidental but real: the process serves the one workbench it was started in, so a misbehaving agent cannot wander. The rules in \"Working safely against the operator's own data\" carry that weight for agents by instruction; the moment the surface stops being one directory, the bound has to exist in the code rather than in a document an agent may not have read."

The MCP surface takes the workbench as a parameter. One registration reaches many workbenches; a CLI invocation stays scoped to one.
