note: "Operator ruling (Paul, relayed by Devin on BARN). The bound is a root directory the server is started with: `dinah mcp` serves any workbench under that root and refuses anything outside it. The default is the workbench discovered at startup, so today's behaviour is what an unchanged registration keeps getting, and reaching further is an explicit act by whoever writes the registration.\n\nWhy this needed ruling before a spec rather than inside one. The single-workbench scope is currently the only thing that stops a head from reaching the operator's own boards, and it holds by accident rather than by intent: the process serves the one workbench it was started in because that is all it ever opened. The moment a workbench arrives as an argument, that accident stops protecting anything, and the discovery walk climbs to the drive root, so an unbounded head on this machine can reach every workbench on it. The workbench document \"Working safely against the operator's own data\" carries that weight for agents today by instruction, and an instruction is the wrong place for it once the surface is machine-driven: an agent that never read the document is exactly the caller the bound exists to stop.\n\nThe two alternatives and why they lost. Serving whatever the caller names is simplest and puts every board on the machine one argument away from a confused client. An explicit allowlist per registration is the most controlled and needs a configuration surface that does not exist, which is a second card's worth of work before this one can start.\n\nWhat the spec still owes on this decision: what the refusal is called and what it says, whether the root is a flag or an environment variable or both, how it interacts with `--workbench` and `DINAH_WORKBENCH` when those name something outside the root, and what happens when the root itself holds no workbench at all."
---
A head serves the workbenches under a root it is started with, and refuses any workbench outside it.
