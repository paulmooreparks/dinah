note: "Operator ruling (Paul, relayed by Devin on BARN): no bound and no skip list. The walk runs once and its answer is cached for the life of the process.\n\nThe measurement this was ruled against, taken by the cycle-2 reviewer rather than argued: a recursive enumeration of the operator's whole source directory visits 27,764 directories across 62 repositories, eight of them node_modules trees, in 13.4 seconds warm. Unbounded and uncached, that is the cost of every call. Cached, it is paid once, and the guidance that a root holds workbenches rather than all of somebody's code carries the rest.\n\nWhy the two alternatives lost. A depth bound makes a workbench deeper than the limit unreachable, which is a silent absence rather than a refusal, and the limit is a number nobody can justify from anything. A skip list helps most real trees today and goes stale by construction, since it can only name the ecosystems somebody thought of.\n\nThe consequence the spec owes a sentence, now narrower than when this was first recorded. A workbench created after the server started is absent from what the listing reports until the server restarts. It can still be named and opened immediately, because an address is a path and a path resolves through a stat rather than through the enumeration. So the staleness is confined to the answer about what exists, and a caller who already knows a path is not asking that question. An earlier version of this note said slug resolution inherited the staleness too; that coupling is gone with the ruling on OQ-1, which withdrew slugs from the surface.\n\nWhat this leaves open for the spec rather than for the operator: whether anything invalidates the cache short of a restart, and whether the listing says how old its answer is. Neither is required by the ruling, and both are cheap to add later, so the spec notes them rather than building them."
