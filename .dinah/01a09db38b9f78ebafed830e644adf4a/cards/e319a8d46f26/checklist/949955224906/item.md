A table-driven unit test reads `SELECTION_POLICIES` at test time and takes as its subject set every entry whose `policy` is `fanOut`. It asserts that subject set holds exactly 13 entries. For each entry it looks the command id up in `ROW_COMMAND_TABLE`, fails if no entry carries that id, and calls that entry's own `invoke` with two actionable rows of the kind it handles and a fake `Wiring` whose hosts record every call. For every subject entry, whatever its effect, it asserts that the real host's members named in `REPORT_CHANNELS` were called exactly once across the whole run, which is the one message the card promises. It then asserts the effect the policy entry's own `effect` field declares: `perRow` means exactly two per-row effects were produced, two spawns for a spawning command and two per-row acts for a non-spawning one, and `oneCall` means zero per-row effects and exactly one effect performed in `finish` carrying both rows' values newline-joined. It asserts the number of entries it exercised equals the size of the subject set. The test carries no exemption list and no skip mechanism, so every `fanOut` entry is driven or the run is red.
