The VS Code extension workstream carries a note saying the extension has been paused since 2026-08-25 and that DinahVisor now holds the urgency for anything with a face. That was true when it was written. It stopped being true when the operator lifted the pause, and since then four cards in that workstream have been built, reviewed, tested and merged, the operator has installed the result and driven it in a live window, and he has named the remaining work as what he wants next.

The note has not been read as history. It has been read as direction. A triage pass on 2026-08-30 demoted a card two priority steps and wrote that nothing was pulling the work forward, at a moment when the operator had said "proceed" on that very card within the hour. Its reasoning was sound and its premise was supplied by the note.

That is the shape worth naming. A stale statement in a place agents read before deciding does not sit inert; it gets used, and the decision it produces looks well-reasoned because the reasoning is fine. The same note is read by every future pass on this workstream, so the cost recurs rather than landing once.

There is a second instance already on the record. A design document still uses Andoneer as its worked example of another implementation of the format, which is filed as dinah-336, and a reviewer built a real argument on it that the operator had to overrule from his own knowledge.

So the work is not only to correct this note. It is to find where else the board and the repository state things that were true once, and to decide what keeps a statement of that kind honest. A dated note that says when it was written and what would end it is one answer. Producing the list with a command over the workstreams, the workbench documents and the design documents, rather than by remembering, is the part that makes this a card rather than an edit.

Filed after the third triage pass to read the note and the first to act on it.
