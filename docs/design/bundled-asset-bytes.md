# Bundled asset bytes

The Windows workflow at 6cc7c49 failed during CLI and desktop initialization because Git converted vendored PUDL CSS from LF to CRLF. Every stored stylesheet blob matches its admitted SHA-256 digest; a checkout with core.autocrlf=true changes those bytes before Go embeds them. Both hosts correctly reject the changed assets.

Repository text files use LF on checkout so source-reading guards receive the same input on every platform. Both vendored PUDL trees must retain the bytes supplied by the release, regardless of the checkout platform or core.autocrlf setting. Repository attributes disable text conversion for these directories, including catalogues, scripts, stylesheets and fonts. Runtime digest validation remains byte-for-byte and continues to reject altered admitted CSS. No runtime normalization or digest substitution is permitted.

The checkout guard creates a temporary Git repository with core.autocrlf=true, stages the catalogue and admitted stylesheets from each host with the repository attributes, removes the working copies, and checks them out again. It compares every byte with the original and validates each catalogue against the checked-out CSS. It also runs the html-safety source-policy extraction against the checked-out Go source. The guard also checks the current working assets, so a build from an already converted tree fails before publication. Existing converted checkouts must refresh the vendored assets from the index after receiving the attributes.

Git documents the -text attribute as disabling end-of-line conversion on check-in and checkout. The contract is documented at https://git-scm.com/docs/gitattributes under Checking-out and checking-in. The regression uses Git checkout-index, documented at https://git-scm.com/docs/git-checkout-index, without launching either application.
