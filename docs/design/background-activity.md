# Truthful chat activity

The current released state projection ignores background tasks and subagents after the foreground turn ends. ExitStatus and restart readiness already count them. AIR task updates emit agent:session and schedule the shared chat/group/team state projection, so event transport exists; the missing state branch turns confirmed work into Idle. This is a demonstrated source defect. The read-only chat inventory confirms the reported PUDL Team Lead currently uses Claude and reports Idle. Its live task list has not been retrieved, so this investigation does not establish which particular runner was active at that instant.

The supported source is the Claude adapter's documented [AIR async task contract](https://github.com/agentclientprotocol/claude-agent-acp/blob/main/docs/air-extensions.md#async-tasks). Dinah already negotiates asyncTasks and consumes spawn, progress and terminal states. A reported autonomous task of type turn represents the agent's own foreground execution. Native subagents use the existing documented subagent path. No task is inferred from prose, process names, elapsed silence or command output. Codex/Ollama translators that do not report equivalent background lifecycle events remain uncovered. Independent terminal windows and applet invocations retain their separate exit accounting; this correction does not attribute them to a chat without a documented owner.

## Shared projection

One sessionhost function projects the existing State snapshot into foreground reason, active task count, running subagent count and busy status. Foreground turn, switching, queued messages and pending steering are Working. A running autonomous turn is Working and is excluded from the background task count. Otherwise confirmed tasks or subagents produce Background work. Paused tasks remain outstanding work, without a claim that their command is executing. Closed and parked sessions carry no background execution claim. Outstanding foreground or queued host intent still holds exit until its existing lifecycle settles it; closing a window alone does not waive that protection.

The execution order remains Stuck, Waiting, Working, Background, Idle. Existing failure and approval/context precedence remains. Every open exec carries tasks and subagents counts when nonzero, including while a higher-priority state is shown. StateCounts adds background; aggregate precedence places it after working and before idle. The shared activity function supplies both exit/restart chat busy inputs and execution projection. A stopped connection clears active task claims and closes the session; late task updates on a closed, parked or replaying session cannot recreate work. Parking and idle cleanup refuse a chat with confirmed background tasks or running subagents.

Front End owns JS/CSS across title/status detail, lists, member menus, team/group aggregates, taskbar and existing In Progress integration. Engine owns Go lifecycle/projection and this document, based on released 36aa5198. exec.state is background, exec.tasks and exec.subagents are optional integer counts. PUDL surfaces restricted to its four execution tokens render background as working with the readable label Background work. No held ACP shutdown implementation is included.

## Verification

Focused checks cover a task continuing after a turn, concurrent tasks and autonomous turns, terminal completion/failure/stop, priority of failures and approvals, late updates after disconnect, clean reopening, park refusal, aggregate counts and state-event propagation. Front End owns the integrated rendered/menu-focus check and direct Release handoff. No live runner interruption, shutdown probe, restart or chat mutation is authorized or performed.

The final command `pwsh -NoProfile -File scripts/go-gate.ps1 ./internal/sessionhost ./cmd/dinah-desktop -run 'Test(Background|WorkActivity|AChatsExecution|CountsChoose|ChatStatesAreSent|ExitGuard|ExitConfirmation)' -count=1` passed sessionhost in 0.136 seconds and desktop in 0.492 seconds. The first run exposed an overly broad guard that dropped outstanding foreground close work from exit accounting. The guard was narrowed to background claims, preserving the existing exit tests without changing their assertions. The transition fixture drives provider notifications through Handler and checks session info against the shared state event, plus exit and restart inputs. No broad suite was run.

The ACP connection reader processes notifications synchronously before it closes Done, and provider detach removes only conversations of the expected provider generation before publishing closed state. Reopened conversations start with new task state. Unknown progress without a new spawn stays ignored. This correction relies on these repository-owned ordering rules, rather than assumptions about OS processes or a provider's unreported work. Historical tasks are not restored as live claims from saved transcript rows.
