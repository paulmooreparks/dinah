# Mentions belong to their chat

Paul's ruling is recorded in docs/design/decisions-redesign.md under "Mentions are not decisions". This standalone host change precedes the remaining settlement implementation.

Decisions and its entry count include ask_person requests and task questions. A plain message mentioning the person has no Decisions row or detail entry. Existing mention-derived rows disappear by projection; original messages, group membership, attachments, replies and chat records are preserved. Existing operation receipts remain available to their established receipt readers.

A mention notification retains the original message ID, group identity when present and sending chat identity. Front End opens the corresponding group or thread at that message, scrolls and marks it, then calls the trusted window method AcknowledgeMention(messageId). A failed open never acknowledges it. Merely loading a background list or marking an Inbox page read does not count as opening the exact message.

Structured request notification cards additionally carry requestId from their authoritative person_requests record, including closed history. Both live notifications:added and saved Notifications reads supply it; old saved cards without the field are resolved from their source during the read. Structured cards retain their Decisions destination even when the Decisions index cannot be read. Plain mention cards have an empty requestId. Neither kind mention alone nor index availability chooses the navigation branch. A source lookup failure fails the read rather than guessing that a structured request is a plain mention.

The host validates that the original is a plain message addressed to the person and has no person_requests source. AcknowledgeMention records acknowledgement separately from Inbox read/dismiss state, keyed by the original message. It creates no answer, approval, rejection or agent message. The watcher dismisses the corresponding saved notification, including after restart or acknowledgement before notification capture. The same acknowledgement can be repeated safely. A new mention remains independent.

A subsequent person-authored text message in the same group also clears its earlier plain mention notifications. A direct reply clears its referenced mention. Neither path settles an ask_person request; structured requests retain their answer controls and operation receipts. Notification dismissal and the existing notification event refresh the person's views.

The settlement contract loses the mention source. Its remaining six source categories are ask_person request, partial ask_person request, local attention report, task single choice, task text and task multiple selection. Mention acknowledgement is navigation attention outside that settlement protocol. The original seven-source freeze must be amended openly by Quality, retaining the old assertions as superseded evidence. This change does not add the deferred stage-two adapters or answer attachments.
