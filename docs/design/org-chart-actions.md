## Calls and values

The existing OrgChart query and its DTO remain unchanged. The page reads the following additional query when opening a context menu or an action form. An empty chatId requests page-level creation actions. A nonempty chatId is a canonical ID returned by OrgChart, never a provider's native ID or a bus address.

```go
func (a *App) OrgChartActions(chatId string) (OrgChartActionView, error)
func (a *App) ApplyOrgChartAction(request OrgChartActionRequest) (OrgChartActionResult, error)

type OrgChartChoice struct {
    ID, Title, Workspace, Provider string
}
type OrgChartAction struct {
    Kind, Label, Token, Href, Explanation, Confirmation string
    Chats, Groups, Workspaces, Providers []OrgChartChoice
}
type OrgChartActionView struct {
    ChatID, Title string
    Actions []OrgChartAction
    Unavailable []OrgChartUnavailable
}
type OrgChartUnavailable struct { Kind, Reason string }
type OrgChartActionRequest struct {
    Kind, Token, ChatID, LeadID, GroupID, Title, WorkspaceID, Provider string
    MemberIDs []string
}
type OrgChartMemberOutcome struct {
    ChatID, Status, Reason string
}
type OrgChartRecoveryTarget struct {
    Kind, ID, Href, Label string
}
type OrgChartActionResult struct {
    Kind, Status, ChatID, GroupID, Message string
    Members []OrgChartMemberOutcome
    Recovery []OrgChartRecoveryTarget
    Created *SessionInfo
    Cleanup *ChatCleanupResult
}
```

JSON fields use lower camel case. Arrays are always present. Optional Created and Cleanup use null when absent. Status is succeeded, partial, refused or failed. Member status is assigned or left_out. A returned ChatID always refers to the logical chat, while Created retains the existing SessionInfo shape for the normal frontend chat-opening path. Errors before a usable action result exists use the bridge error; completed or partly completed operations return their result with a nil error.

Action kinds are assign_team, make_lead, create_team, create_group, start_chat and delete_chat. Every mutation is pageWork, and the action query is pageQuery. The calls use the existing person-facing bridge authority. They add no agent tool, grant, approval bypass or provider capability. Token detects stale preconditions and grants no authority.

An action's Href names the chart's addressable form, preserving its current filters and folds through the normal page state mechanism. The action state uses action and chat query parameters; the page may add lead, group and member parameters for a draft choice. Tokens and confirmation state do not go into the address. Recovery Href values are generated by the host's existing page-address helpers, with encoded identifiers. Front End never builds a bus address or native ID from a display title.

## Legal action representation

OrgChartActions captures one settings/header view, resolves through logicalChatMembersFromSettings and uses canonical aliases for every offered choice. It reads existing local bus relations and existing local cleanup eligibility. It starts no provider, discovers no native history and opens no chat. Workspace choices use opaque saved workspace record IDs. Provider choices come from the product's configured local provider inventory without connecting to an account. Only explicit start_chat may start a provider.

Actions contains legal operations only. Each descriptor includes the choices needed for its form, so the page does not infer legality from node shape. Unavailable explains absent operations but carries no Token or Href. A repair row, lifecycle reservation, unresolved allocation or ambiguous alias offers no management operation on that chat. A missing eligible group produces an explanatory make_lead unavailability, rather than an empty submit form. A deletion refusal uses the cleanup row's authoritative reason.

The host re-resolves the subject and all submitted choices before dispatch. It compares the action token against the current relevant ownership, reservations and team/group structure, excluding transient working-state counters and display-only changes. A stale token returns refused with a refresh explanation and no mutation. A forged action, unrelated field or choice not offered for that action is refused. All existing operation checks run again at execution, including cycle prevention and current cleanup refusals. The query is advisory about current legality; it does not promise a transaction across settings, runtime state and the bus database.

Assignment choices identify existing teams by canonical lead ChatID. Create Team may select a chat that already reports to another lead, as the current nested-team operations allow. It does not allow a chat to lead a second team channel. Ordinary group choices exclude team channels and groups that fail the current conversion checks. Creating a team is allowed at the page level and from a chat, with that chat preselected as lead; creating a group may preselect the context chat. Start a Chat does not silently use the context chat's workspace or agent program.

The deletion confirmation says: "Move this chat to the Recycle Bin? It will disappear from Dinah now and can be restored for 30 days. Its agent program's history is kept until final deletion. Linked documents and document drafts are unchanged." The action label is Delete Chat…, matching the existing cleanup surface. A final-deletion command is outside this contract.

## Partial completion and recovery

Create Team is a composition of existing operations and does not claim atomicity. Validation occurs before group creation. If creation fails, no conversion is attempted. Once a group is created, every later result carries its GroupID and a recovery target to that existing group. If conversion fails, Status is partial and the message says the ordinary group was retained. If conversion succeeds with left-out members, Status is partial and Members lists all assigned and left-out chats. The result never reports an unassigned chat as assigned.

The recovery representation offers make_lead for the retained group only when that conversion remains legal, plus a link to inspect the group. It does not offer another create_team as the continuation of that attempt. Front End retains the returned group identity, so retrying conversion cannot silently create a second group. It shows every member outcome before returning to the chart.

A lost bridge response to a creation has an unknown outcome. The page never automatically retries a create or start request. It refreshes local chart/group state and says the outcome must be checked before another creation. This stage introduces no promise of exactly-once allocation and no parallel allocation journal. Release's receipt work remains separate. A returned new chat remains available even if a subsequent chart refresh fails; the host does not delete it to tidy a presentation error.

Successful actions retain the existing team, bus and chat removal events. The page refreshes the real query after a structural mutation and preserves focus and scroll where their targets still exist. No mutation is triggered by merely checking a choice, loading a form or refreshing the chart. Front End owns keyboard access equivalent to each box's context menu and the URL-addressable forms. Drag assignment remains deferred.

## Verification and handover

They prove legal-action omission and reasons, forged and stale-choice refusal, canonical switched identities and no provider activity in action queries or relation mutations. Assignment tests cover a move, an idempotent repeat, a self-edge and a descendant cycle. Conversion tests cover an eligible ordinary group, an existing different lead, left-out members and a retained group after second-step failure. The recovery submission reuses that GroupID and creates no second group.

Creation tests cover duplicate group titles, provider failure and a successful chat start with no prompt. A positive provider counter distinguishes an intentional start from query activity. Deletion uses the real Recycle Bin path and verifies working, pinned, live-allocation and protected queue-owner refusals, whole-chain staging and old-lease refusal. The underlying cleanup suite remains unchanged.
