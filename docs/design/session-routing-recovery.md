# Durable chat recovery

Recovery keeps the logical recipient that owns the waiting messages. The person chooses a supported provider and an offered model, or explicitly selects the configured provider default, before confirming saved-history recovery. The selected model is checked against the allocated session's options and applied before ownership commits or a waiting message runs. A conflicting continuation remains a separate recipient with its own history and deliveries. Recovering the original creates a fresh native conversation from that original's saved context and never merges or acknowledges the conflicting recipient's queue.

Settings are the commit authority for recipient ownership and explicit continuation bindings. A transfer journal in the same settings document records allocation intent before contacting the provider, then the returned native target, then prepared saved context. The recipient mapping, explicit successor and committed transfer phase change in one validated settings write. Delivery stays held throughout an incomplete transfer. A restart can distinguish an allocation whose receipt is unknown, a known allocated target and a committed binding. It never invents a native ID or repeats an allocation automatically.

An interrupted transfer requires a new explicit recovery confirmation. That confirmation discloses the prior transfer; starting again retains its record and does not send to its candidate. No model turn is issued during allocation or preparation. The previous candidate may exist at the provider, and the interface does not claim it was deleted or delivered. A known committed binding takes precedence over historical ancestry, so pre-existing distinct-recipient forks do not select a destination by file enumeration order.

Allocation and model configuration use the existing ACP paths. [Session setup](https://agentclientprotocol.com/protocol/v1/session-setup) specifies a unique returned session identifier and capability-gated loading. [Session config options](https://agentclientprotocol.com/protocol/v1/session-config-options) supplies the offered model selector and its confirmed value. The implementation does not infer native persistence from an empty allocation or treat Resource not found as proof of deletion. A provider that exposes no model selector cannot apply an explicit model choice; recovery reports that failure and keeps the original recipient and queue.

Provider failure does not prove deletion. The durable failed-open owner records the actual target and suppresses automatic attempts until an explicit retry or verified routing change. Its generation joins the page and fallback and retires both on completion. Unchanged recipient conflicts cannot be bypassed by Retry or a newer message.

The settings additions are `chatBindings`, `chatTransfers` and `chatTransferHistory`. Existing documents need no migration. An incomplete transfer overrides ancestry resolution with its original source, holds that source's recipient and keeps a known candidate hidden until commit. A committed binding remains authoritative through later switches. An older waiting hold is reconciled only against that committed chain, its unchanged recipient and the retained target history. Refresh Recovery Status retries this local reconciliation after a failed cleanup write. None of these operations alters bus delivery rows.

Recovery consent covers saved history, recipient and transfer state, provider defaults and the selected model. The normal final history and authority checks still run after allocation. A changed confirmation requires another review. Existing interrupted candidates remain recorded when a later explicit attempt supersedes them. Separate recipients are never combined, including when their histories share an ancestor. Multiple legacy branches without a committed binding are held for explicit recovery rather than selected by file enumeration order.

The incident snapshot at 23:01 on 1 November confirms continuing failures at 22:58 and 22:59. The 18:50 notice was old, but its failure was not resolved. A private coherent SQLite backup, settings, both saved histories and logs are retained under `.diagnostics/recovery-20261101-230125` with hashes. No live recovery or state patch is authorized by this implementation. Provider-native recovery uses supported session allocation and normal reviewed handoff, with no dummy turn or fabricated persistence file.

## Focused verification

The focused Go checks exercise page/fallback generations, failed resume, unchanged failures across restart, recipient conflicts, allocation failure, all precommit transfer phases, rejected commit writes, explicit model selection, ordinary provider switches and delivery through the original bus recipient. The category fixture runs both Codex and Claude recovery with arbitrary identities and checks that the other recipient's delivery remains pending and both original histories remain byte-identical. It also recreates an older waiting hold after commit and verifies reconciliation from settings loaded from disk.

The final affected Go run passed sessionhost and every selected desktop case except the Claude category fixture, whose fake connection returned a Codex-prefixed native ID. Correcting that fixture to return the selected provider's ID made both category branches pass in the isolated rerun (0.931 seconds). The earlier complete selected run with model selection passed in 17.754 seconds. Runtime code was not changed to accept a provider/ID mismatch. The earlier continuation retry fixture now obtains fresh consent after allocation failure, preserving its pending-handoff assertion. The additional ambiguous-branch fixture passed in 0.559 seconds and demonstrates refusal before provider contact followed by an explicit committed destination, with the other branch preserved.

The existing session-recovery browser suite passed. The waiting-chat-recovery fixture passed after scoping its recovery-control query to the original window, and its final run passed in four seconds with an empty failure file. It verifies offline original-history review, provider/model choice before allocation, cancellation, conflict retention and separate retry/reload behavior. The final screenshot was inspected. A first launch lacked the new worktree's browser module path; using the existing installed dependency resolved setup without changing product code. Syntax and whitespace checks passed. These results and the retained initiating failures are under `.diagnostics`; broad regression and live provider recovery were not performed. Release owns the necessary production build and delivery.
