# Notification activation and native placement

On released 9ed2c459, the Windows notification message handler calls winNotifier.bringForward. That first invokes the app callback supplied by startHostNotices. The callback unconditionally calls Wails WindowUnminimise and WindowShow. Pinned Wails 2.11.0 implements WindowUnminimise with its window Restore method, so a maximized window is restored before the notifier can perform its own conditional native activation. The notifier already checks IsIconic before SW_RESTORE, but that check happens after the destructive callback.

Windows activation will have one owner. The app supplies no Wails activation callback on Windows; the existing Windows notifier locates the application's main window through its documented process/window enumeration path. It calls ShowWindow(SW_RESTORE) only when IsIconic reports minimized, then SetForegroundWindow. A normal or maximized window receives no restore or placement operation. Windows maintains the previous maximized state for restoration of a minimized window. No geometry or global placement settings are rewritten. Other platforms keep the Wails callback, guarded by WindowIsMinimised before un-minimising.

Microsoft documents [IsIconic](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-isiconic), [ShowWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindow), [WINDOWPLACEMENT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-windowplacement) including WPF_RESTORETOMAXIMIZED, and [SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow). Wails documents WindowUnminimise as restoring the preceding dimensions and position, and WindowShow as showing a hidden window. It has no separate documented foreground activation method, so Windows continues to use the existing documented Win32 route. Foreground requests remain subject to Windows policy.

Focused checks use fake window operations for maximized, normal, minimized-from-maximized and minimized-from-normal states, including repeated activation. They check that the Windows app callback is absent so no earlier Wails restore can occur. Tests create no native window and send no input. No desktop automation, notification injection, live activation or restart is permitted.

The desktop and hostnotify focused checks passed in 0.188 seconds and 0.275 seconds on 2 November. The command used scripts/go-gate.ps1 for ./cmd/dinah-desktop and ./internal/hostnotify with filter Test(WindowsNotification|NotificationActivation|StructureSizes|CopyUTF16|HostNotice), count 1. This compiled the changed Windows backend and ran the existing notification-policy and Win32-structure checks. Whitespace checks passed. Native foreground behavior was not exercised on Paul's desktop. Release owns the installation build and publication; no broad regression gate is required.
