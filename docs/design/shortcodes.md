# Shortcodes a build adds

The content applets edit a Markdown dialect with shortcodes, written `{{name}}`, `{{name:arguments}}` and `{{name}}…{{/name}}` (yavc.app, `docs/markdown-dialect.md`). A product built from Dinah's source whose documents are pages on a site has shortcodes of its own, the site's macros as the product's converter writes and reads them, and the applets did not know them: an occurrence was drawn as the text it was written as and marked as a problem, nothing offered to insert one, and the Files applet's preview drew it as text. Two openings fix that, added on 10 November 2026. Nothing in this repository names a shortcode; Dinah's own build registers none.

## The registry

`internal/shortcodes` is the registry. A product registers a `Set`: its `Catalog`, a list of descriptors (name, kind among inline, block, container and span, a description, its parameters and an example), and `Render`, which draws one occurrence from a `Request` (the name, the raw argument text after the colon, the whole shortcode as written and, for a container, the Markdown of its body) as HTML. A container's HTML holds one `<slot name="content"></slot>` element where the body goes; the applet draws the body itself, so the body stays the engine's and only the shell is the product's. The raw argument text is passed rather than parsed, since a product's grammar may allow spaces in positional arguments and names such as `{{@user}}`. `Render` asks each set in turn and a set answers `ErrUnknown` for a name it lacks.

A descriptor may say two more things about its shortcode. `Prefix` is one punctuation character the shortcode can be written with in place of its name and colon, so that a set whose descriptor has the prefix `@` has `{{@value}}` read as that shortcode with the argument `value`. `Managed` says the product keeps the shortcode with a tool of its own, as a product does for a discussion thread it stores in the document: the applets draw a managed shortcode, leave it out of the Insert menu and do not change it on the page. A request says, in `Kind`, how the applet read the occurrence. The applet reads a container that opens and closes within one line as a span, and the set then draws it to sit inside that line. For a container or a span the request's source may be the opening alone, because the applet has the body.

A set may also have forms, by implementing `Former`. `Form` reads one occurrence, as written, as a form (a title, a line of help, and fields that each have a name, a label, the present value and, where the value is one of a few, the choices), and `Build` writes the shortcode back from the form's values, returning a `FieldError` that says which field is wrong when a value cannot be written. The forms are the set's because the argument grammar is the set's; the applet shows fields and never composes a shortcode's arguments itself. A shortcode with no form is changed as text.

Four App methods take the registry to the page: `ShortcodeCatalog`, `RenderShortcode`, `ShortcodeForm` and `BuildShortcode`. The content host gives them to the applets as two services on `pudlHost.contentWorkspace`.

- `shortcodes(context)` is the call yavc.app's host contract already documents for a host's extra shortcodes. It returns `{ shortcodes: [{ name, title, description, kind, params, example, prefix, managed }] }`, which the applets merge into completion, hover and the Insert menu. Until 10 November 2026 Dinah offered an object here instead of a function, so the catalog never reached the applets.
- `shortcodeHost`, version 1, draws and changes an occurrence. `render(request)` takes `{ name, kind, args, source }` and returns `{ html }`, `form(source)` returns a form or `null`, and `build(kind, values)` returns `{ source }` or `{ error: { field, message } }`.

The applets' side of `shortcodeHost` was asked of yavc.app on 10 November 2026 and arrived the same day in v0.2.55, which is pinned (yavc.app, `docs/host-shortcodes-contract.md`). The engine learns the host's names and kinds, so that a container opens and closes and an inline shortcode is one unit in the page view. The page view draws an occurrence through `render`, and shows the occurrence as it is written when the host fails or takes longer than four seconds. Pressing an occurrence opens the form from `form` and writes the result of `build` back. The release sets bounds a build's catalog has to stay inside: a name is a lowercase letter followed by lowercase letters, digits or hyphens, 64 characters at most, and there are 256 entries at most. It draws for the screen alone, so printing and Office export refuse a document that has a build's shortcode in it.

## The Files preview

The Files applet's preview pane, and anything else that previews a resource of a source, draws Markdown with Dinah's own renderer. A kind of source may instead draw its documents as its site would: `workspaces.SourceKind.Preview` takes the document's Markdown and returns blocks of HTML with the line each starts on, and the problems found, and `previewProvider` uses it for a document of that kind. The product's converter already renders a page's preview from the same conversion a publish makes, so what the pane shows is what the site will show.
