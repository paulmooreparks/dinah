# Retained requests for the person

Attention banners are signals for a retained Notifications card. Bus read receipts are not acknowledgements of those cards. A restored group can refresh and mark deliveries read without the person opening that group, so the earlier read-based dismissal loses the only durable route back to the request. Windows receives a tray balloon through Shell_NotifyIcon and a taskbar flash; those signals have no application-owned history. Permission cards also used to exist only while their provider request remained pending.

Each bus mention, failed relay and permission alert keeps its own durable identity. The page presents one summary per sending chat, combining repeat requests into a count and showing the latest request's first line, source and timestamp. It retains each underlying identity for exact dismissal. The summary opens the latest group message or direct bus thread, or the permission's chat. Opening a target acknowledges only the requests present when navigation started. A new request arriving during that operation remains waiting. Pending permissions remain actionable beside the chat's composer.

Dismissal, opening the requested chat/group and an actual answer end the corresponding attention. Reading an inbox or refreshing a background group does not. Cancelling a provider ends its permission channel but leaves the historical attention until the person opens or dismisses it. Undismissed attention is exempt from the ordinary report age/count pruning; the existing notification store byte limit still reports a write failure rather than silently evicting attention.

Notifications retains its window and filter geometry. Cards append in stable arrival order, existing cards keep their places, and grouped attention reserves one fixed card height with internal scrolling. Arrival does not raise a window or focus a control. The status/taskbar count comes from the same grouped model. Existing broker-owned human-request cards keep their own answer lifecycle and are not replaced by a summary that could hide their response controls.

The implementation uses the existing notification persistence and dismissal methods. It adds no page API or native desktop automation. Focused Go tests use fake notifiers and temporary state; browser checks run headless. The Architectural Principles remain at `C:\Users\paul\OneDrive\Documents\Architectural Principles.md`.

The mention capture cursor advances only over successfully stored requests. New capture includes already-read deliveries because a background view can read before the watcher. On upgrade from the old fixed cursor, only the unread backlog is imported; historical read requests cannot be distinguished from acknowledged requests once their old tombstones have expired. Existing active cards are preserved. The migration does not promise to reconstruct earlier lost cards.

Permission attention is saved before publishing the actionable permission event. Only a successful claim of a pending permission counts as its answer. A stale answer after cancellation leaves the historical request intact. Clear All also dismisses a snapshot of stored identities rather than clearing records that arrived during its asynchronous operation.
