# Pause requests during a running turn

The review on 14 November 2026 found that Codex already implements the documented active-turn input path. Pause Chats and Restart uses the shared capability check and steering submission, which reaches `turn/steer` with the active `expectedTurnId`. Acceptance does not prove that the model followed the instruction. The restart still waits for completion. The [OpenAI App Server documentation](https://learn.chatgpt.com/docs/app-server#steer-an-active-turn) defines this exchange. A cancellation request cannot carry a reason and is unsuitable for asking for a safe stopping point.

Claude's ACP adapter documents a separate `_session/steering` extension in its [producer-owned example](https://github.com/agentclientprotocol/claude-agent-acp/blob/main/examples/steering.ts). Its initialization must advertise top-level `_meta.steering.supported: true`. Dinah will use that capability for text input when hooks have not reached the chat, requesting `_meta.steering.idleBehavior: "promptRequired"`. An `injected` receipt confirms acceptance; `promptRequired` with `noRunningTurn` means nothing was consumed. Any other outcome or lost response stays unconfirmed and is never automatically replayed. No detached fallback is requested. Existing reached hooks keep their current priority. Images remain unsupported by this extension adapter.

Devin and Claude already use documented PostToolUse context injection once their hooks have bound the agent session to the chat. The [Devin hooks contract](https://docs.devin.ai/cli/extensibility/hooks/overview#output-format) and [Claude hooks contract](https://code.claude.com/docs/en/hooks#posttooluse-decision-control) define `hookSpecificOutput.additionalContext`. This waits for a hook boundary and does not interrupt a tool. A chat without reached hooks or another advertised capability keeps waiting normally.

Ollama has no documented input insertion into an outstanding HTTP chat request. Dinah owns that provider's tool loop and already inserts queued text in the next complete exchange using the documented [chat messages array](https://docs.ollama.com/api/chat). An outstanding request or tool finishes first.

Plain [ACP v1](https://agentclientprotocol.com/protocol/v1/prompt-turn) documents cancellation and a prompt turn but no mid-turn message insertion. Dinah will not send a concurrent ordinary prompt or invent a reason field for cancellation. ACP v2 remains a draft and is outside this change. Unsupported agents retain the recorded waiting behavior and the existing explicit Restart Now choice. No provider is interrupted automatically to make a restart happen.

Protocol stand-ins verify pause submission, acceptance, turn completion and the durable pause record. They cannot prove a real model's safe-point compliance or delivery timing during long tools. All fixtures use isolated invented state without a visible window. The evidence is in [the verification record](../review/pause-provider-input-2026-11-14.md).
