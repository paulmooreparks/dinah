# Group composer recipient controls

Paul requested removal of the recipient explanation panel beneath the composer in bus 2501. This scoped correction starts from released 50a49b. The bottom area retains its existing input, attachment and send controls, with no recipient summary, disclosure or typing-dependent explanation row.

The explicit Mention Everyone action moves to the existing group toolbar after the reading control. It calls the existing mention insertion function, which records the mention in the draft and passes its ID through the existing send filter. The button does not send a message. Plain text still supplies no explicit recipient IDs, leaving the existing server rules for passive group notices and team-lead routing intact. Removing or changing mentions continues to affect only the recipients represented in the current text.

Team-member chats retain their existing Open Team Chat path. That path preserves the group draft and adds the selected member through the same mention function. No second composer or recipient implementation is added to the member window. The shared bottom panel and its styles, input listeners and routing-refresh hook are removed rather than hidden.

The toolbar remains available independent of typing. Its buttons use the existing PUDL toolbar keyboard behavior and natural wrapping at narrow widths. The existing Members, Add Chats, Turn Budget and reading controls keep their order; the explicit recipient action follows them. No bundled PUDL asset changes or new glyph dependency are introduced.

The scoped browser checks cover plain group and team send payloads, explicit pointer and keyboard mentions, explicit everyone selection, draft preservation through close/reopen and the member-to-team route.
