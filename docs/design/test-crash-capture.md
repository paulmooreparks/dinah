# Test crash capture

The Windows full-Go job on master 5c84503 lost the desktop test process's fatal output and reported status 2 after 303.025 seconds. Neither that status nor the elapsed time establishes whether it was a panic, timeout or external termination. The job kept no per-test artifact. Its wrapper supplied no timeout option, and the retained environment shows empty GOFLAGS. Go's documented test default is ten minutes. The active test cannot be recovered from the available plain job output.

Desktop TestMain calls runtime/debug.SetCrashOutput before releasing its standard handles. This uses the [documented crash-output API](https://pkg.go.dev/runtime/debug#SetCrashOutput), independent of how a runtime implementation finds standard error. When DINAH_TEST_DIAGNOSTICS_DIR is set, it must be an absolute directory. Setup creates it if needed, then creates desktop-crash-<PID>-<random>.log. Each process owns a unique file. Setup errors fail before handle release; they are never suppressed. When the variable is absent, ordinary local tests retain their existing behavior.

SetCrashOutput duplicates the supplied descriptor, so TestMain closes its own file after configuration. This changes no test result or termination policy. Release owns creating the artifact directory for full-Go CI, capturing per-test output and uploading available diagnostics after failures while preserving the test exit status. Engine owns desktop TestMain and its regression guard. No production executable is changed.

TestCrashOutputSurvivesHandleRelease starts a child test process that panics after TestMain has released its handles. It checks that the child fails and that its uniquely named crash file contains the panic marker, test function and goroutine stack. In an artifact-enabled run, the intentional crash uses a separate crash-guard subdirectory so it cannot truncate parent evidence. The subprocess has a bounded diagnostic timeout. The guard passed locally on Windows in 0.310 seconds through the FIFO wrapper. It is listed in guards.json.

This correction restores observability. It does not resolve the original desktop exit. A bounded comparison of desktop tests on 5c84503 and pre-file-access 289fb62 will use identical diagnostic setup, per-test JSON, explicit six-minute test limits and retained crash files. Six minutes narrows the documented default rather than increasing a failed test's deadline. Neither a passing reproduction nor a new diagnostic deadline will establish the missing original cause.
