# Group window resolution

This correction implements the group-window requirements from bus messages 2053, 2171, 2173 and 2176. The canonical architectural source remains [Architectural Principles](C:/Users/paul/OneDrive/Documents/Architectural%20Principles.md).

The current opener invents a room identity when an exact-name overview lookup misses. Restored windows bypass that opener and use their saved path directly. Both paths can then interpret an overview miss as deletion. These are independently confirmed defects. A read-only native capture on 31 October at 12:11 found Paul's current group window already keyed as `dinah-cleanup`. That observation does not establish its earlier key or explain his earlier false-deleted banner. His incident remains open until the affected path is reproduced or checked on the installed build.

`BusResolveGroup(key)` is a read-only UI resolver. It returns `{state, room?}` with `resolved`, `not-found` or `ambiguous`; operational failures reject through the bridge. Only `resolved` includes a room. Resolution tries stable key, current title, then recorded historical titles. A current title wins over an old alias, and multiple historical matches are ambiguous. The bus send resolver retains its existing stale-title refusal. The database retains no deletion record, so `not-found` means unavailable and does not justify a deleted banner.

Opening by title resolves before creating the window. A restored legacy address displays a loading state while it resolves, then rekeys to the stable room name. Once resolved, the window retains that canonical name through later renames. The saved UI state records the canonical identity as well as its address, so a restored canonical window rejects a different group returned through title fallback. An overview miss triggers authoritative resolution while preserving the last known room, loaded conversation and draft. Loading, unavailable, ambiguous and operational-error states are distinct from empty history. Async results must be current for their window and resolution generation before they can change state.

Canonicalization preserves message and mention targets. Duplicate aliases converge on the canonical window. Saved drafts move to the canonical draft key when it is empty; a distinct existing draft is preserved as a selectable alternative, including its mention identities. The composer never combines unsent text automatically. Alternative drafts remain saved until selected or explicitly discarded. Existing in-memory attachments on the canonical window remain untouched; saved drafts continue to follow the existing rule that attachment contents do not survive restart.

The regression must cover stable/current/old names, current-title reuse, ambiguity, unknown and deleted rooms, delayed overview and resolver replies, restoration, duplicate drafts, message/mention targets, a rename during resolution, failed refresh and a later overview omitting a known room. It must also reject obsolete results after newer resolution or disposal. Backend and browser gates share the existing test slot.
