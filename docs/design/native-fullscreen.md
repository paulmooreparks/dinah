# Native full-screen mode

Dinah uses PUDL 0.87.0 at `051a8a3fd9ef26f73010355ca8e6b8a62fb23d90`, including the native-window API introduced in 0.86.0. Both asset locations contain its complete tagged distribution. The application uses `pudlNative.attach` for the topbar application menu and native Minimize, Restore and Close controls, which appear only while the host reports fullscreen.

F11 toggles the native desktop window. View > Full Screen exposes the same operation and shows its checked state, and command search and Keyboard Shortcuts include it. Modified F11, key repeats and composition do not toggle. F11 remains available while a dialog is open so the person can leave fullscreen without dismissing their work. Escape retains its existing menu, dialog and content-window behavior. Ordinary maximization does not display the fullscreen controls.

The host uses Wails 2's documented `WindowFullscreen`, `WindowUnfullscreen` and `WindowIsFullscreen` APIs. [WindowUnfullscreen restores the preceding dimensions and position](https://wails.io/docs/reference/runtime/window/). Dinah remembers whether the native window was maximized and explicitly restores maximization on exit. It captures the ordinary placement before entering and preserves that placement when closing in fullscreen. Fullscreen is not persisted across launches.

Native actions are serialized independently of application state. Mode transitions wait up to three seconds for the native query to report the requested state. The frontend reads that authoritative state after actions, on focus and once per second while visible. It does not infer native mode from browser fullscreen, viewport dimensions or PUDL content-window state. A timeout is reported and later state reads still reconcile the controls. Wails 2 provides no documented active-window query, so the adapter does not claim to track native activation.

Minimize calls the native host. Restore leaves fullscreen. Close uses the existing Wails Quit path, including the interruption confirmation, UI-state flush and save-failure handling. No separate forced-close route is introduced. PUDL's content-window Window menu remains separate from the native application menu.

Extension frames receive a Dinah-specific F11 listener alongside the unmodified public SDK bridge. It uses the existing typed `hostCommand('toggle-fullscreen')` request. The parent validates the frame through its existing MessagePort lifecycle and invokes the same native adapter. The listener cannot inject arbitrary keyboard events. Extension-local text inputs retain their focus through F11 because toggling changes no mounted content. SDK 0.1.2 adds host-initiated `focus-prepare` tokens to the existing focus-return protocol. Pointer or keyboard focus moving from a frame to native chrome records its child target before returning. The parent sends a return only after focus reaches that live frame; stale tokens cannot restore a superseded excursion.

The optional PUDL annotations module remains unloaded. Native controls retain their physical corner placement in narrow views and RTL, as defined by PUDL's native-window contract. The application does not make its topbar an OS drag region.

Unit tests cover normal-placement capture, maximization restoration, idempotent Restore, native minimize/close routing and unavailable/unknown actions. Browser integration checks cover F11 from an opaque frame and the host document, checked View state, native controls and narrow edge alignment. These checks distinguish a simulated browser adapter from native-host verification.

The full 72-suite browser run passed in 148 seconds before the final native-menu focus follow-up. The focused extension, keyboard and workbench checks cover that follow-up separately. SDK 0.1.2 passed tests and vet on Windows, Linux and macOS CI. The native Windows smoke test confirmed titlebar removal through Win32 style inspection, restoration of normal coordinates and size, restoration of maximization, actual native minimization, and preservation of draft text and focus. It used the authenticated page against a production-tagged native executable and did not measure WebView2 rendering performance. A missing-production-tags fixture was discarded before native evidence was collected. The existing terminal-close test timed out in the package run and passed alone; vet passed.

Paul raised a visual mismatch between the first native controls and existing PUDL window controls, including the application-menu glyph. PUDL 0.87.0 corrects the button dimensions and raised rounded surfaces while retaining edge-reaching hit areas. Dinah uses its documented `icon` option with `/dinah-mark.svg`. Both vendor copies remain unmodified tagged assets.

With PUDL 0.87.0, the browser regression compares native-button width, height, corner radius, raised background and shadow against an ordinary floating-window button. It verifies the loaded Dinah icon, actual View-menu activation, and edge alignment at narrow width. Light and dark screenshot review confirmed the shared styling. Native mode and command availability flush the command registry synchronously so an immediately opened View menu cannot show the preceding mode or transition state. Repeated and composing F11 events are consumed without reaching another shortcut dispatcher.
