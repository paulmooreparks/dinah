# Exit confirmation

Dinah asks for confirmation before closing while chats are working, switching providers or carrying queued submissions. Idle, open chats do not trigger the guard. The prompt also covers live native terminal sessions, executing applet actions without safe replay, signed extension calls, and unfinished host requests or built-in terminal commands. Native terminal sessions are included even at a shell prompt because their process state cannot be restored.

The existing applet replay contract supplies the recovery distinction. Pure actions and persisted human requests can recover through the broker; once-only or unknown replay classes require confirmation. Retired brokers remain included until their active invocations finish. Direct extension calls have once-only replay and remain included until their callback scope ends. Action counts are combined into a single warning so a broker invocation and its extension callback are not reported twice.

The bridge exposes a generic call-lifetime observer. Dinah classifies known queries, presentation changes and the close protocol as safe to interrupt; an unclassified object method is conservatively included as unfinished work. New methods must receive an explicit recovery classification. Browser workers use `BeginExitWork` and `EndExitWork` around built-in terminal commands and startup profiles. The registration outlives a UI cancellation until the underlying command finishes or unwinds.

Every native close route passes through the same guard, including the operating-system close control, the application Exit command, fullscreen Close and update restart. The callback vetoes the initial close and emits a confirmation request. A PUDL dialog focuses Cancel; Enter on that button and Escape both cancel. The native window stays open while the page answers. A five-minute unanswered request expires without exiting. Request identities reject stale replies and duplicate native close events do not create another dialog.

Explicit confirmation permits the existing UI-state flush. Failed or timed-out saving discards the consent and leaves the window open. A later close requires confirmation again. If work begins during an initially idle layout flush, the final close callback checks again before allowing exit. Cancellation abandons a pending update restart and leaves active work running.

The frontend confirmation uses PUDL because [Wails 2 does not support custom message-dialog buttons on Windows or Linux](https://wails.io/docs/reference/runtime/dialog/). The implementation does not depend on custom native button labels or an unsupported default-button policy. A missing or unresponsive page cannot silently approve exit.

Unit tests cover idle versus active chats, cancellation, unfinished request registration, replay classification, stale replies, timeout, one approval across the save handshake, and work starting while the first flush is pending. Browser checks cover the displayed reasons, focused Cancel, Enter, Escape and explicit Exit. The Lua regression checks registration during a running worker and release after Ctrl+C.

The production-tagged Windows integration test confirmed that Cancel preserves unfinished work and leaves the native host running. A second Close with explicit Exit Dinah completed the existing layout handshake, wrote native placement and ended the host. The final PUDL 0.87.0 browser run passed all 72 suites together in 147 seconds. Bridge, broker and extension package tests passed. The full Go run hit the existing terminal-close timeout; that test passed alone. Vet passed.
