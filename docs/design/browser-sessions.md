# Browser session lifetime and revocation

Paul approved TM-03 in message 3327. This contract was recorded before implementation, whose source work followed BL-04's passing local recovery checks. The candidate is on rewritten history. The [Architectural Principles](C:/Users/paul/OneDrive/Documents/Architectural%20Principles.md) apply.

Browser sessions retain their issue time and last successful use. A token expires when either 30 days have elapsed since its last use or 90 days have elapsed since issue. Expiry boundaries are inclusive. Successful authenticated use advances last use at most once per hour and never changes issue time. The stored activity can therefore lag actual use by less than one hour. A future last-used time is treated as the current time after a backward clock correction, while the absolute deadline still comes from the original issue time. Invalid timestamp syntax or database failures deny access.

The idle and absolute windows are documented persisted settings shared by every process opening the bus. They are positive whole-day values with defaults of 30 and 90. The command-line browser-sessions settings command will display or change them. Invalid settings must fail clearly without changing the stored policy. Changing policy applies to existing tokens on their next validation; it does not renew their issue time.

The database stores the SHA-256 digest of each random bearer token, never the cookie value. The existing token column holds that digest, and token_version=1 identifies the hashed format. Validation and single-browser revocation hash the supplied cookie before lookup. A copied stored digest cannot authenticate as a cookie. The additive migration marks pre-existing plaintext rows as version zero and invalidates them; every existing browser signs in once. Message history and deliveries are unchanged. Old database copies may still contain obsolete plaintext tokens, which the upgraded database no longer accepts. Validation parses timestamps as times and advances activity transactionally so revocation cannot be undone by a concurrent update.

Sign Out removes the current browser token server-side and expires its cookie. Sign Out Everywhere removes every browser token and invalidates outstanding single-use sign-in codes in the same transaction, so a previously issued link cannot silently sign a browser back in. Both actions use authenticated same-origin POST requests; a GET never revokes a session. The authenticated page exposes ordinary PUDL controls for both actions. The command-line browser-sessions sign-out-everywhere command provides the same supported revocation operation when the browser is unavailable.

Expired, revoked or unknown cookies receive the existing sign-in page with clear text that the sign-in is no longer valid and a fresh command-line sign-in is required. The page clears an invalid cookie and must not cache authenticated content. A sign-out response redirects to that signed-out state. Neither operation restarts the app or contacts a provider.

An open event stream must stop delivering when its token is revoked or expires. Its periodic validation will check authority without treating passive keepalives as a new use; otherwise a forgotten open tab would keep its own idle window alive. Ordinary authenticated HTTP requests count as use. Reconnecting an event stream validates authority but likewise does not advance activity. Revocation cannot retract content a browser has already received.

The guards use an isolated database and a fake clock. They cover idle expiry, activity extending only the idle window, absolute expiry despite repeated activity, exact boundaries, migration of older tokens, malformed stored times, current-browser revocation, global revocation and sign-in-code replay. HTTP tests cover the sign-in-again response, cookie removal, same-origin POST requirements and stream termination. A legitimate session remains usable within both windows. No live browser token, desktop or listener is needed for these tests.

The supported settings commands are `dinah browser-sessions settings`, `dinah browser-sessions settings --idle-days 30 --absolute-days 90` and `dinah browser-sessions sign-out-everywhere`. Each window accepts 1 to 3650 whole days. The policy is stored in the bus database's singleton web_session_policy row. Authentication metadata updates do not advance the message change counter, avoiding refresh loops caused by the act of authenticating a request.

The focused clock, legacy-schema migration, concurrent revocation, HTTP sign-out, event-stream termination and command-line guards pass. The HTTP guards use in-process request handlers and no listening socket. The affected bus, web and command-line selection passed before migration, and all three profile guards passed on the mapped candidate. The security reread requested hourly renewal, backward-clock tolerance and hashed storage before shipment. The added guards count actual UPDATE statements within the hour, exercise clock corrections and the absolute boundary, reject a copied digest, and invalidate an actual plaintext legacy database.
