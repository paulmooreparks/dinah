Judgements at the first start

Mockup, 20 November 2026. Press the buttons in the flyout; Start Over begins again.

Judgements

Bottom bar

What is proposed

  • At the first start, once an agent program works, the Judgements flyout opens by itself over its item in the bottom bar and asks one question. It opens by itself only that once.
  • Until the question is answered, the bottom bar's item says "Judgements: Set Up" in place of "Off", and pressing it shows the same question again. Nothing is chosen for the person.
  • The question says what judgements do, which model would answer them, and what a day of them may cost at most, in the provider's own unit.
  • Turn On chooses the default provider and its default model, sets the starting budget, and tunes the choice of model in the background. Not Now leaves judgements off and the item at "Set Up". Judgement Settings opens the page with nothing chosen.
  • With an API key billed per token the question says so and gives the budget as money where the provider reports prices.
  • With no working agent program there is no question yet. The item says "Judgements: Needs an Agent" and the flyout says what to do.

The starting budget

  • A new person has no history, so the figure ships with the product: 200 calls a day. That is about four times what a busy day used in the records so far.
  • The product turns it into the provider's unit from what a call measured there. A call through Claude or Codex now costs a small fraction of what it did, since a judgement no longer carries the agent's tools and settings with it.
  • After two weeks the Judgements page offers a figure from the person's own records and changes nothing by itself.
