    Bottom bar and tray

    New in this mockup

    • The answer area is smaller. It has no heading, sits under a rule, shows about five lines and scrolls for more, the ticked chats included.
    • The prompt is the chat window's. It grows with what you type, up to six lines, and scrolls after that. Enter asks and Shift+Enter starts a new line. It grows upward, so nothing under it moves.
    • Ask always acts at once, for windows and for chats. Type "stop the Pricing team" and it is stopped.
    • A task always says what it would do and waits for Run. A task that acts on chats lists them under the sentence, each with a tick, in What It Does. The separate box is gone.
    • A typed request must say its team exactly. Type "stop the Billing team": nothing is done, and it says which teams there are.
    • What Undo cannot take back is said in the result, and Run does not offer it a second time.

    Try

    • Type a long request over several lines with Shift+Enter, then Enter.
    • Type "change all of the Pricing team members from Claude to Devin" and press Enter, then Undo.
    • Open Edit Tasks, add a task that asks "change all of the Pricing team members from Claude to Devin", save it, choose it in the assistant, untick a chat, and press Run.

    Chats and teams

    • The assistant acts on chats as well as windows. Three of the stand-in chats are a team called Pricing. Type "change all of the Pricing team members from Claude to Devin", "stop the Pricing team", or "tell the Pricing team to report where they are".
    • A task lists the chats it would act on, each with a tick, under what it says it would do. Untick one to leave it out. Run acts on the ticked ones only.
    • It says what Undo can take back. A switch of provider can be switched back, and Undo does that. A stopped turn and a sent message cannot, the answer says so before Run, and Undo stays disabled after.
    • A chat that is working is switched when its turn ends, and the list says so beside it.
    • These can be saved as tasks like any other request.

    What changed from the second mockup

    • Nothing runs on a press. Pressing a task chooses it, and "What It Does" says what it would do to which windows, by name. Typing a request and pressing Ask does the same.
    • Run does it. Run is disabled until there is something to run, and again once it has run. After Ask, Run has the focus, so Enter a second time runs what you typed.
    • Undo is beside Run, in the foot, and puts the windows back as Run found them.
    • A question, such as What Needs Me?, is answered in the same place and has nothing to run.

    Try

    • Press Tidy Up, read which windows it would close, then press Run, then Undo.
    • Type "find all the windows for the pricing work", press Enter, read the answer, and press Enter again.
    • Press one task and then another without pressing Run. Nothing moves.
    • Open Edit Tasks and close the assistant. The window has the list's own buttons in a bar, the task with Save, and Try This Task, where Try It says what the words would do, Run does it and Undo puts it back. Run is disabled until Try It has been pressed for the words as they are.

    What is the same

    • The assistant is reached from the tray and a key only, and is one popover of one size.
    • Tasks are a list that scrolls, and Assistant Tasks is a window of its own with a starter set.
    • It can only do what you could do by hand in the window. Closing is limited to idle chats and documents with nothing unsaved.
