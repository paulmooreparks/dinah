# Decisions answer stability

The null-box failure exposed a page defect. The fourth combined run on `31797c52` reproduced the exception at decisions-answer-layout.js line 15, with all twenty other suites passing. The third run had already failed the same geometry assertion without throwing. The original layout suite has not been changed.

Inspection reproduced a null delivered-row box after delivery. In the fixture, the waiting row had measured 333 pixels high. Delivery removed that row and inserted a new row, whose first intrinsic estimate was 120 pixels plus its 13 pixels of border and padding. The later message moved by 200 pixels and returned on the next frame. The new delivered row was attached when the diagnostic captured it. This was a change to the reading surface, so adding a wait to the geometry test would have hidden the defect.

Delivery now reuses the attached waiting row and replaces its contents. This preserves its position and the size remembered by the browser. Decisions rows also use the fixed card height as their initial intrinsic estimate. Both sizes use one CSS value. The [design note](../design/decisions-answer-card.md) links the documented sizing rule and explains why the initial estimate is also required.

The new decisions-answer-stability suite records the synchronous delivery result and eight subsequent animation frames. It checks that the row remains attached, that the estimate equals the card height, that the card remains visible, and that the card, later text, scroll position, window, composer and taskbar do not move. It does not wait for delivery to settle before measuring. Fixture setup finishes before the measured delivery starts.

The same regression was run against the unchanged base and the correction. Its frame records are attached as JSON beside this note. The base used `auto 120px` and removed the waiting row. It shrank the row from 333 pixels to 133 pixels and changed the transcript scroll position from 350 to 150 before restoring both. The answer was not visible in one of the nine recorded frames. The correction preserves the row and its geometry, and the answer is visible in all nine frames. Both final comparison runs took four seconds; the base failed and the correction passed.
