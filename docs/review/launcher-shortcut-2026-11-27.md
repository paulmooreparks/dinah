# Launcher keyboard command checkpoint

The branch starts at 7aa7797d and registers Launcher under View after Refresh. The command owns Mod+Shift+X, calls the public launcher toggle API with returnFocus, and supplies the menu row, command-search listing, Keyboard Shortcuts entry and command tooltip. The shared registry displays Mod as Cmd on Mac and Ctrl elsewhere.

The host call uses the documented shape agreed for PUDL 0.112.0: toggle(root, { returnFocus: document.activeElement }). The currently bundled PUDL 0.110.1 ignores that option and returns focus to its opener. This checkpoint must not ship until the library adoption and receiving establish prior-focus restoration. No vendored files changed.

The new launcher-shortcut suite exercises Windows Control and the Mac Command platform branch, each with ribbon off and on, from no focus, an actual yavc Editor, a chat prompt and a Terminal running the real terminal renderer against a counted bridge. It verifies opening, search focus, closing, prior focus, unchanged window geometry and selection, scroll positions, text and terminal input, as well as registry listings and the ribbon command tooltip. Native macOS and installed-window acceptance remain separate.

The test failed on the unchanged base with all sixteen opening journeys unbound and command listings absent. After host registration, every opening and closing journey and every listing passes. The final receiving run on 0.110.1 fails only the twelve prior-focus assertions. Its private receipt is under the temporary directory dinah-launcher-shortcut-final-pending. The initial fixture visibility wait incorrectly required xterm's intentionally hidden helper textarea to be visible; that setup failure is retained separately, and the fixture now waits for the ready terminal and attached helper.

Documents-menu, host-menus-order and ribbon passed in the focused neighbour selection. The title-launcher narrow assertion failed both here and on an isolated unchanged base. Diagnostics preserved the original interactions and captured a viewport update before delivery of the window resize event. In the failing sample, innerWidth was 640 while compact remained false, left was 49 and right was 673. The resize handler switched to compact mode before the first recorded animation frame; all following frames had left 0 and right 640. The suite must wait for the public compact state before its existing geometry assertion. That timing correction is separate from the product command.
