# Desktop test collector sweep

The test-only sweep is in progress on engine/test-collectors, based on 15afdc2c. It replaces callback-owned slices with a mutex-protected collector whose readers receive copied snapshots. Shared provider call logs, aside requests and notifier observations use the same collector. Local event collectors and the judge connection reader were corrected as well. Existing assertions remain in place. Synchronous builders and collectors already protected on both read and write remain unchanged.

The first whole-package run stopped producing output and did not terminate after its Go deadline. It had no crash capture configured, so that run establishes only a failed execution. The focused recovery selection then passed three times in 17.524 seconds with race detection, all vet analyzers and an empty crash file.

A second whole-package execution used crash capture and an external deadline for the owned process tree. It reproduced the Windows runtime traceback while TestRecoveryAllocationFailureAndRestartRetainOwnership was the current reported test. The capture contains runtime.lastcontinuehandler, runtime.winthrow, an unexpected return PC for runtime.systemstack_switch and a second failure in runtime.hexdumpWords with unsafe.Slice length out of range. The last reported test does not establish the original exception's source. No data-race warning preceded this failure. The process did not terminate after the twelve-minute Go deadline and was stopped by the external thirteen-minute bound. Later repetitions did not run because the first failed.

This is not a passing package or proof that every race is gone. The secondary runtime traceback has recurred after the collector changes, but its original exception remains unidentified. Raw logs contain local paths and stay outside the repository. No test was skipped or weakened, and no product source changed. The next diagnostic must preserve the Windows exception before the failing traceback obscures it, while the collector audit and complete package runs remain open.

Lead's follow-up in 9623 separates the runtime investigation from this collector correction. The next whole-package gate must record the Go version and test counts for repeated non-race runs followed by repeated race runs. A matching documented Go issue is required before attributing the Windows exception to the race detector. The source audit changes only tests and adds no race-detector workaround. This frozen candidate is available for bounded receiving review; it has no full-package clearance.
