internal/qualityrequestsettlement/acceptance.test.cjs contains 48 top-level cases. Missing receiving bindings fail. These checks cover host authority, durable results and source projections. ## Execution and binding

QUALITY_REQUEST_SETTLEMENT_BINDING names an absolute CommonJS module exporting async open({scenario,source,...input}). It returns run() and close(). Run node --test --test-concurrency=1 internal/qualityrequestsettlement/acceptance.test.cjs through pwsh scripts/with-test-lock.ps1. A receiving fixture uses isolated stores, invented people/chats/services and counted external peers. close() joins and releases all owned work, including failed cases. No real account, visible desktop, installation or remote write is authorized by this freeze.

The binding retains the actual App dismissal entry, authenticated chat invocation context, registered consumer withdrawal port, original request stores, task Question owner and reviewed AskPerson operation, durable receipts and notice dispatch. An authenticated actor cannot be simulated by adding person or owner fields to an otherwise untrusted payload. The service is registered through its real boundary, with an independent positive callable control. Its withdrawal port cannot be used to answer or dismiss. Run supplies raw operations and observations, never a predicted successful mutation or fabricated authority result.

Each observation returns scenario, source, artifactDirectory, complete providerRequests and actionRequests, remoteWriteAttempts, protectedBefore/After and unrelatedBefore/After. Count attempts before refusal. Protected records include document and draft bytes, native history, group membership, approval/grant records and retained message/unknown-operation stores. Unrelated records include other open and closed requests and their completion obligations. Snapshots are detached values captured after setup, with only diagnostic logs and capture timestamps excluded from equality. Retain unfiltered raw values beside every canonical representation.

The canonical record has id, revision, status, request, sourceLink, answers, settledAt and actorKind. status maps the actual source disposition, without turning an unknown or revoked result into dismissed/withdrawn. answers preserves actual question IDs and payloads. before and after carry the record, all applicable open views and addressable closed history. Ordinary sources expose notifications and decisions projections; task sources also expose the task-run host projection. A projection may be read without rendered UI, but cannot be synthesized from another view's result. Counts come from each actual consumer path.

The common receipt keeps actual operationId, id, revision, state, outcome and settledAt. Refusal observations retain code and text, and before/after compare stable authority. A legacy adapter's existing error/receipt shape may be translated to this vocabulary only while retaining the original response. Source history and notice wording must identify the real actor and outcome. No-answer assertions inspect payload presence, not truthiness, so empty text, empty selection or an implicit recommendation cannot pass as absence.

## Fixtures and cases

The seven owned source fixtures are explicit request, person mention, local attention report, partly answered request, legacy task choice, typed text and typed multiple selection. Each dismissal and withdrawal must persist its terminal record before returning, remove exactly that entry from every open projection and release the actual asking waiter without an answer. Task fixtures reread the durable operation disposition after Rebind and restart and invoke the original operation identity, counting any reasking. A partial fixture has prior answers and one final unanswered question. Its prior answers must remain byte-equivalent. The remaining question receives no invented answer.

Each owned source also races Answer, Dismiss and Withdraw. Use distinct operation identities and real concurrent calls synchronized at the actual authority/commit boundary. The answer is the fixture's final answer, so it would close that request if it won. The binding cannot serialize all contenders or manufacture a winner. Require one accepted terminal operation, one record and one logical completion. Preserve prior partial answers and source linkage. Three additional task-text controls deterministically exercise both settlement-first and revocation-first schedules for cancellation, generation invalidation and shutdown, using private boundary gates rather than sleeps or widened waits.

Authority cases attempt dismissal as the asker, another chat, a service and a forged person. Withdrawal attempts use another chat with the same group, workspace, provider or title, forged owner metadata, removed/unresolvable owners and the real owner. Consumer cases vary service, workspace, task, generation and the admission chat independently, and attempt service answering/dismissal. Raw trusted invocation context must be captured separately from caller payload. A valid person or owner positive control must succeed after the corresponding unauthorized attempts fail.

Command representation cases retain Dismiss, Withdraw and the fixture's pre-existing answer commands in open, answered, dismissed, withdrawn, ownerless, owner-unavailable and stale-generation states. The manifest supplies expected answer-command names from the fixture's existing source contract, before querying commands. Disabled entries retain a reason and no callable authority. callable is an observation of the actual offered invocation handle, not a copy of enabled. Person-context Dismiss is enabled for the valid open fixture. Ownerless and unavailable owners have no enabled withdrawal.

Receipt cases repeat a committed ID and perform scoped lookup. Original receipts, settledAt and obligations must remain identical. Changed input with the same actor/command ID refuses, as do foreign receipt lookup and a new operation against a closed source. The same string ID is separately used by another authenticated actor and another command on independent eligible source requests to prove that scoping does not create unrelated collisions. Operation ID boundary cases use the supplied scalar strings and invalid values verbatim; do not pre-truncate or normalize them.

Late-settlement cases exercise stale open revision, stale task generation, prior cancellation and shutdown. They invoke both dismissal and withdrawal, compare the actual beforeRestart snapshot with afterRestart, and require no answer or question replay. A stale open revision returns revision_changed. Cancellation and invalidation retain their distinct recorded meaning. Do not obtain a synthetic expected terminal snapshot from the tested output.

Fault cases inject before authoritative commit, at an unknown commit response, after a committed response is lost and during completion dispatch. The precommit case stays open, has no committed lookup result, terminal record or completion, and remains unchanged through passive reconciliation. Other cases reconcile an actually committed operation under its original ID, with no new settlement attempt or new ID. A lost response alone cannot be treated as proof of noncommit. The source settlement and notice obligation must be observed together at independent durable-read checkpoints. commitSnapshots include before, gated write boundaries and after; they must never expose a closed source without its one obligation. Keep the raw independent reads, injected fault receipt and writer sequence as evidence. A boolean claiming atomicity does not replace those observations.

Both legacy person adapters must settle an actual task question before its notification projection changes and release its waiter without an answer. Raw sequence records establish sourceCommitSequence before projectionCommitSequence. Restart must preserve that source receipt. The adapter uses its real public input shape; the binding cannot bypass it by calling the new entry directly.

Offline asker cases settle against an actual unavailable recipient, retain the obligation and original source identity across restart, then restore that same recipient and observe one logical completion. No member or replacement chat may receive it. Owner withdrawal is admitted through a previously authenticated owner invocation whose caller remains valid while its reply/notice destination is unavailable; it cannot bypass the removed-owner refusal. An ownerless report records local dismissal without inventing a chat notice or recipient.

The Cannot be delivered fixture retains real message bytes, an unresolved allocation/unknown result and its original task state. Dismissal changes only the report's disposition. A later incident gets another identity or revision and remains open against the old dismissal. Missed-event cases drop only the person-view projection event after commit, then repair by real reread and restart without repeating settlement. Existing answered single/text/multiple results and pending typed schemas remain unchanged, and invalid answers retain their former refusals.

## Evidence requirements and status

Retain raw request bodies, authenticated actor context, command descriptors, source rows, notice obligations, receipt lookup results, all projection snapshots, task waiters/results, events, fault checkpoints and restart/rebind results. Logical completion counts identify one durable notification obligation across dispatch retries; separate physical dispatch attempts remain visible. Counter controls must exercise real notice dispatch, provider requests, action dispatch and refused/successful remote writes in isolated positive cases. Prove the assertions reject disposable observations with a forged owner success, an invented empty answer, duplicate completion, erased partial answer, changed protected bytes or a closed source missing its obligation, after unchanged controls pass.

This is an independent freeze for receiving, not host or product acceptance. Engine retains implementation, schema migration and binding responsibility. Missing seams remain unverified. Any assertion correction must name its reason and retain the original failure. Syntax validation will be recorded separately. No settlement implementation has been read or run by Quality.
