# Recycle Bin inventory publication

The branch engine/bin-publication starts at master 4219f37a. It fixes a reproduced late publication after successful binning. When an open team member entered the Recycle Bin, its lead still carried the old team counts when removal returned. The scheduled team and chat-state passes subsequently removed the binned member from the count. SavedChats includes that state in its guarded runtime hash, so a publication during the next read produced the same changed-identities refusal Paul reported.

The production correction runs the existing team and chat-state publication passes after retention and provider release finish, before the successful removal returns. Those passes keep their existing serialization. Later timer passes can still publish new work, but they have no outstanding bin-related state change to apply. No retry, delay or guard weakening is added. Binning still preserves native history, archived bytes and the existing retained team relationship.

The new regression holds only timer scheduling, then invokes the actual scheduled publication paths explicitly. This avoids sleeping through the timing window. On the uncorrected base, the first regression detects that the returned lead still counts its removed member as idle. A second regression schedules those actual passes after the real inventory snapshot and reproduces the exact SavedChats refusal. The inventory method has a private receiving boundary for that deterministic schedule; the public path supplies no callback. A third control changes a genuine saved identity during the snapshot and must still be refused by the original consistency guard.

The first two regressions pass ten repetitions each with race and all-analyzer vet, for twenty passing cases in 37.630 seconds. The original failing receipts are retained in the session. An initial new-fixture expectation that binning dissolved the team was corrected before the production change: binning retains the relationship for restoration, and the remaining lead receives updated counts. No existing assertion changed. Tests use invented chats and isolated homes. No real provider, live customer state, browser, installation or registry action was used.

The focused cleanup, restore, deletion, SavedChats, Start Chat and publication race/all-vet selection passed 36 tests and subtests in 41.912 seconds. The genuine-identity-change control passed, with no data-race warning or panic. All checks ran through the canonical shared pwsh lease using Go 1.26.10 on Windows amd64.
