# Task questions in Notifications

The implementation is on frontend/task-question-ui from master ff236bd1. It consumes Engine's frozen task-question API at 43c1e14f. That isolated host stage is not included in this frontend branch. Engine retains host ports and receiving bindings. The confirmed representation and sequencing decision are recorded in docs/design/task-question-presentation.md.

Notifications shows the question with the service name, task title, workspace and stable question time. Open Task uses the host's addressable destination through the ordinary workbench navigation. When the page is unavailable, the card explains why and remains answerable. The card has the offered radio choices and Send Answer. It has no Open Chat, dismissal, synthetic chat identity or transcript answer row.

The question state and renderer live in task-questions.js. The future Decisions redesign can subscribe to this state and use the same answer path. The present Decisions page remains unchanged under Lead's message 9090. Notifications uses its existing question glyph, PUDL tokens, live announcement, taskbar count and filtering. It does not open a window or move keyboard focus on arrival.

Initial load and reconnect read PendingTaskPermissions independently of the existing chat question snapshot. Host keys identify immutable questions. Duplicate events cannot reset a selected or pending answer. Ended keys stay suppressed during the page lifetime. Per-key read versions prevent an old snapshot from reviving an ended question or removing one that arrived while the query was pending.

Sending uses only Answer(key, optionId). It disables every mounted copy. A confirmed answer ends the shared question; cancellation and revocation use the same terminal event without claiming an answer was sent. After an uncertain answer, the UI reads authoritative pending state before allowing another explicit submission. A failed status read keeps sending disabled. A lost response after an accepted answer removes the question without sending again. The result region reserves its height, and a Check Question Status control remains reachable.
