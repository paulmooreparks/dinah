Quality froze these checks on a branch from master a3826b6b in response to Engine 9771 and Lead 9745. The sole new design input is docs/design/typed-task-questions.md at e511142d3a9d10c3207224840a0be272907724a6. Quality read that contract before any implementation handover. Existing task-host freezes remain unchanged.

The executable gate is internal/qualitytypedquestions/acceptance.test.cjs. Its twelve top-level cases cover declaration bounds, text Unicode scalar counting and byte preservation, strict JSON and invalid Unicode, offered multiple selections and order, legacy separation, copied snapshots, concurrent settlement, four withdrawal causes and lack of service authority. Empty, one, sixteen, over-limit and malformed inputs are explicit. A 16384-emoji answer must pass; a 131072-byte valid body must pass, while a larger body must refuse. These are host checks. Rendered and installed acceptance remain outside this freeze.

## Binding contract

QUALITY_TYPED_QUESTION_BINDING names an absolute CommonJS module exporting async open(). It returns the operations below. A missing binding fails. The caller runs node --test --test-concurrency=1 internal/qualitytypedquestions/acceptance.test.cjs through pwsh scripts/with-test-lock.ps1 with the shared dependency path if needed. close() must join and release all fixture work, including after assertion failure. Each test uses a fresh isolated App and invented task stores.

The binding must retain actual task Review, fresh person-confirmed Begin, reviewed AskPerson permit and operation identity, Question owner, durable receipt, trusted App submission and cancellation machinery. ask(request) validates and starts that real operation, returning {ok,key,error}; it must not block waiting for the person's answer. The fixture uses no provider, remote document or action execution to ask a question. A successful key identifies the actual pending asking. An invalid declaration produces no question and cannot change stable task authority. Diagnostic validation logs may be retained separately.

pending(view) reads the actual pending representation for notifications or decisions, without replacing its key, owner, text, options, askedAt or typed fields. The view names identify two consumers of the same host state; they do not require rendered UI. answer(key,raw) passes the exact supplied JSON string to App.AnswerTaskQuestion. answerBytes(key,bytes) passes an exact Go string made from those bytes to the same entry point so invalid UTF-8 is observable before JSON replacement. Neither method may pre-validate or repair the input. Both return {ok,error} from actual success or refusal. answerLegacy(key,id) uses the existing App.Answer path. result(key) reads the completed operation's durable result after settlement.

snapshot() returns a detached canonical snapshot of stable pending-question authority, offered schema, operation receipts, task generation, protected records and native/action/write counters. Rejected answers must leave that snapshot unchanged. Exclude only wall-clock capture metadata and diagnostic error logs. Retain the unfiltered raw snapshot alongside it. mutatePendingCopy(key,patch) obtains an actual copied pending value inside the host process and mutates that copy, including option slices, so this control tests host copying rather than transport serialization alone.

settlement(key) returns {durableResults,answeredEvents} from the real journal and counted task:answered events, filtered only to that key. answer() waits for the recorded completion boundary before returning. Concurrent answers must overlap at the real authority boundary; the binding cannot serialize them or choose a winner. withdraw(kind,key) drives actual Cancel, task-generation change, removal or App shutdown. restart() reconstructs the App from the same isolated stores. A removed or interrupted question cannot be recreated by replaying AskPerson. New asking with the same title uses a new operation identity and key.

callService(name,input) attempts the named answering route through actual CallService/service exposure. It returns a real unknown-method or authority refusal, never a harness-generated denial. The fixture is a registered task consumer and must not receive an answering port. It cannot use a supplied person flag, owner or generation to grant authority.

observations() returns artifactDirectory, raw providerRequests and actionRequests, remoteWriteAttempts, protectedBefore/After and questionReplayCount. Count attempts before refusal. Keep raw host requests/responses, schemas, input bytes, events, task records and result receipts. Prove counter sensitivity separately with positive controls through the real boundaries, then isolate their effects from the no-work scenarios. Deliberately altered captured results must fail the assertions for a wrong Unicode count, reordered selection, consumed invalid answer, duplicate settlement or erased question obligation.
